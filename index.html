01 The question

What makes a multi-agent
workflow work?

Building multi-agent systems still relies on trial and error. Manual studies explore a handful of communication patterns; automated optimizers keep a task-specific winner and discard the rest.

We turn those intermediate designs into evidence. By retaining complete search trajectories, then mining workflow code and prompt templates, we identify design principles that persist on held-out searches.

Read the full abstract +

Designing large language model (LLM) multi-agent systems (MAS) still relies on trial and error and informal “folk wisdom.” Manual studies test only a few communication structures or topologies (e.g., sequential, parallel, shared-memory, or debate), while automated optimizers discard search trajectories after selecting a task-specific workflow. We present a two-phase pipeline for mining reproducible design principles from workflow code and execution traces. We repurpose AFlow’s MCTS optimizer across six composable operators and 26 deterministically verified Enigmata tasks, retaining all intermediate rounds to build a corpus of 28,568 executable workflows. A sandboxed AutoResearch loop then mines orchestration code and prompt templates under an L₀-penalized validation objective and tests candidate principles on held-out searches. Across 300 feature-mining trials, we identify effects that persist on held-out searches across three levels of workflow design: workflows beginning with independent solvers and one-shot aggregation (Star-first) perform worse (Δ = −0.045); persistent shared documents (SharedMemory) outperform debate (Δ = +0.135); and prompt specificity and placeholder-based context routing yield gains comparable to communication-structure selection (Δ = +0.118). More broadly, our pipeline and results show the feasibility of turning discarded search trajectories into a statistical testbed for discovering and validating multi-agent workflow design principles.

03 How it works

Search for workflows.
Then search for principles.

Two phases connect executable designs to statistically testable patterns.

PHASE 01 / SAMPLING

Keep every evaluated design.

AFlow composes six operators over 20 MCTS rounds, across five independent runs per condition. Deterministic Enigmata verifiers evaluate fixed bundles of reasoning problems.

Code + prompts + verified outcomes
PHASE 02 / ANALYSIS

Mine, then verify.

A sandboxed AutoResearch loop proposes interpretable features under an L₀-penalized validation objective. Entire searches are kept together across training, validation, and test splits.

Search-level splits · Held-out verification
